# agent-vcr v0.3 技术方案：HarnessMetadata / Pairwise HarnessDiff

## 1. 版本定位

v0.3 只解决一个问题：

> 同一个模型、同一个任务，两次 run 为什么行为不一样？
> v0.2 能告诉我们“行为哪里分叉”；v0.3 要补上“两个 run 的 harness 有哪些差异”。

v0.3 的核心产物是：

```text
HarnessMetadata
HarnessDiff
HarnessInspect
HarnessDiff + BehaviorDiff 的关联摘要
```

v0.3 不做批量 benchmark，不做 Matrix Compare，不做 Regression，不做 LLM Explain，不新增大规模 agent adapter。

## 2. 版本边界

### 2.1 v0.3 必须做

- 定义 `internal/harness` 包。
- 为每个 run 生成可序列化的 `HarnessMetadata`。
- 从已有 trace / metadata / repo 文件 / config 中提取 harness 指纹。
- 支持 `agent-vcr harness inspect <run-id|latest>`。
- 支持 `agent-vcr harness diff <run-a> <run-b>`。
- 支持 JSON 输出。
- Pairwise harness diff：只比较两个 run，不做多 run matrix。
- 将 harness diff 与 v0.2 behavior diff 做轻量关联，输出 “可能相关的行为影响”。
- 保持隐私优先：默认存 hash、摘要和存在性，不存完整 prompt / AGENTS.md / tool schema 原文。
- 保证 `internal/harness` 不依赖具体 adapter。

### 2.2 v0.3 不做

- 不做 Matrix Compare。
- 不做 benchmark.yml。
- 不做 baseline / regression。
- 不做 PR risk score。
- 不做云端 dashboard。
- 不做 LLM explain。
- 不做 deterministic replay。
- 不新增 Claude/Kimi/MCP adapter，除非只作为 detector 的 fixture。
- 不改变 v0.2 的 behavior schema 核心语义。
- 不把 harness diff 写成因果推断，只输出“差异”和“可能关联”。

## 3. 背景：v0.1 / v0.2 / v0.3 的关系

```text
v0.1: trace foundation
  normalized trace.Event
  event-level diff

v0.2: behavior diff
  trace.Event → behavior.Step
  BehaviorSignature
  first behavior divergence
  behavior metrics

v0.3: harness diff
  run → HarnessMetadata
  HarnessDiff
  HarnessDiff + BehaviorDiff 关联摘要
```

v0.2 回答：

```text
这两次 run 行为从哪一步开始不一样？
```

v0.3 回答：

```text
这两次 run 的 harness 哪些地方不一样，可能影响了这些行为差异？
```

## 4. 核心概念

## 4.1 Harness

在 agent-vcr 中，harness 指影响 agent 行为的执行环境与脚手架组合：

```text
model
adapter
prompt scaffold
AGENTS.md / rules files
tool schema
MCP config
permission mode
sandbox mode
context policy
memory/config
retry strategy
repo baseline
agent-vcr version
agent CLI/client version
```

模型只是 harness 的一部分。

## 4.2 HarnessMetadata

`HarnessMetadata` 是单次 run 的 harness 指纹。它必须：

- 可 JSON 序列化。
- 可缓存。
- 可比较。
- 默认隐私安全。
- 不依赖具体 adapter。
- 允许 adapter 补充扩展字段，但核心结构保持通用。

## 4.3 HarnessDiff

`HarnessDiff` 是两个 `HarnessMetadata` 的 pairwise comparison。它应输出：

- 相同项。
- 不同项。
- 缺失项。
- 可能影响行为的差异项。
- 和 v0.2 BehaviorDiff 的关联摘要。

## 7. 数据模型设计

## 7.1 HarnessMetadata

建议结构：

```go
type HarnessMetadata struct {
    SchemaVersion string            `json:"schema_version"`
    RunID         string            `json:"run_id"`
    Source        string            `json:"source,omitempty"`
    GeneratedAt   time.Time         `json:"generated_at"`
    Repo          RepoFingerprint   `json:"repo,omitempty"`
    Model         ModelFingerprint  `json:"model,omitempty"`
    Adapter       AdapterFingerprint `json:"adapter,omitempty"`
    Prompt        PromptFingerprint `json:"prompt,omitempty"`
    Rules         RulesFingerprint  `json:"rules,omitempty"`
    Tools         ToolsFingerprint  `json:"tools,omitempty"`
    MCP           MCPFingerprint    `json:"mcp,omitempty"`
    Permission    PermissionFingerprint `json:"permission,omitempty"`
    Sandbox       SandboxFingerprint `json:"sandbox,omitempty"`
    Context       ContextFingerprint `json:"context,omitempty"`
    Config        ConfigFingerprint `json:"config,omitempty"`
    Extra         map[string]string `json:"extra,omitempty"`
    Warnings      []HarnessWarning  `json:"warnings,omitempty"`
}
```

## 7.2 Fingerprint 类型

每个 fingerprint 类型建议包含：

```go
type HashRef struct {
    Algorithm string `json:"algorithm"`
    Value     string `json:"value"`
    Source    string `json:"source,omitempty"`
}

type FileFingerprint struct {
    Path      string   `json:"path"`
    Exists    bool     `json:"exists"`
    Hash      HashRef  `json:"hash,omitempty"`
    SizeBytes int64    `json:"size_bytes,omitempty"`
}
```

原则：

- 文件内容默认只保存 hash。
- prompt / tool schema / rules 默认不保存原文。
- 可保存摘要字段，但必须可配置和脱敏。
- 路径要规范化为 repo-relative path。

## 7.3 HarnessDiff

```go
type HarnessDiff struct {
    SchemaVersion string              `json:"schema_version"`
    LeftRunID     string              `json:"left_run_id"`
    RightRunID    string              `json:"right_run_id"`
    Same          []HarnessField      `json:"same,omitempty"`
    Different     []HarnessFieldDiff  `json:"different,omitempty"`
    Missing       []HarnessMissing    `json:"missing,omitempty"`
    Summary       string              `json:"summary,omitempty"`
    Impact        *BehaviorImpact     `json:"impact,omitempty"`
    Warnings      []HarnessWarning    `json:"warnings,omitempty"`
}
```

`HarnessFieldDiff`：

```go
type HarnessFieldDiff struct {
    Path       string `json:"path"`        // e.g. "rules.agents_md.hash"
    Label      string `json:"label"`       // e.g. "AGENTS.md"
    Left       string `json:"left,omitempty"`
    Right      string `json:"right,omitempty"`
    Severity   string `json:"severity"`    // info | medium | high
    Category   string `json:"category"`    // model | prompt | rules | tools | permission | context
    Summary    string `json:"summary,omitempty"`
}
```

## 8. Harness 检测来源

v0.3 应优先从这些来源检测：

## 8.1 Existing metadata

来自 v0.1/v0.2 的 `metadata.json`：

- run_id
- source adapter
- git sha
- branch
- capabilities
- summary

## 8.2 Trace events

来自 `trace.ndjson`：

- run_start model 字段（如果有）
- permission_mode（如果有）
- tool_call / tool_result 中的 tool schema / tool names
- mcp tool names
- user_prompt 的 prompt hash（如果存在）
- raw event 中可安全提取的元信息

## 8.3 Repo files

默认检测：

```text
AGENTS.md
CLAUDE.md
.cursor/rules/**
.codex/**
.agent-vcr/config.yml
package.json
go.mod
pyproject.toml
pnpm-lock.yaml
package-lock.json
```

注意：

- 只存 hash，不存全文。
- 不要强依赖这些文件存在。
- 缺失只作为 missing / warning，不是错误。

## 8.4 Config files

检测：

```text
.agent-vcr/config.yml
.codex/hooks.json
.codex/config.toml
```

其中 `.codex` 相关只做通用 “client config fingerprint”，不要在 harness 包里写 Codex adapter internals。

## 8.5 Environment / execution mode

仅收集安全、低敏信息：

- OS
- arch
- sandbox mode（如 metadata 中已有）
- permission mode（如 trace 中已有）
- agent-vcr version
- adapter name/version

不收集：

- 环境变量原文
- API key
- HOME 绝对路径中的用户名，除非脱敏
- 私有目录结构

## 9. CLI 设计

## 9.1 harness inspect

```bash
agent-vcr harness inspect latest
agent-vcr harness inspect <run-id>
agent-vcr harness inspect latest --json
agent-vcr harness inspect latest --refresh
```

输出：

```text
Harness: run_001

Model:
  name: gpt-5-codex
  source: trace.run_start

Rules:
  AGENTS.md: present sha256:abc...
  CLAUDE.md: missing

Tools:
  tool names: Bash, apply_patch, mcp__filesystem
  tool schema hash: sha256:def...

Permission:
  mode: workspace-write

Warnings:
  - prompt hash unavailable
```

## 9.2 harness diff

```bash
agent-vcr harness diff run-a run-b
agent-vcr harness diff run-a run-b --json
agent-vcr harness diff run-a run-b --with-behavior
```

默认可以包含简短 behavior impact。如果计算 v0.2 behavior diff 失败，应降级：

```text
Harness diff computed.
Behavior impact unavailable: behavior signature missing.
```

不要让 harness diff 因 behavior diff 缺失而失败。

## 10. Behavior Impact 设计

v0.3 不能做强因果推断，只能做关联摘要。

正确表述：

```text
Behavior impact:
- First behavior divergence occurred at file discovery.
- Harness changed AGENTS.md and tool set.
- These changes may be related, but agent-vcr does not infer causality.
```

错误表述：

```text
AGENTS.md changed caused the agent to fail.
```

## 11. 隐私策略

默认隐私策略：

- 存 hash，不存原文。
- path 使用 repo-relative。
- 对 prompt / tool schema / rules 默认不保存原文。
- JSON 输出不包含 secret。
- redaction 仍应用于 harness 输出。

可选未来功能：

```yaml
harness:
  capture_raw_prompt: false
  capture_raw_tool_schema: false
```

但 v0.3 不建议实现 full raw capture。

## 12. 与 v0.2 的兼容

v0.3 不应破坏：

```bash
agent-vcr behavior latest
agent-vcr behavior diff run-a run-b
agent-vcr behavior metrics latest
```

v0.3 新命令是新增：

```bash
agent-vcr harness inspect latest
agent-vcr harness diff run-a run-b
```

## 13. 测试策略

必须有：

- HarnessMetadata JSON 测试。
- File hash 测试。
- AGENTS.md 检测测试。
- missing file 测试。
- trace-based model/permission/tool detection 测试。
- harness diff same/different/missing 测试。
- harness diff JSON 输出测试。
- behavior impact fallback 测试。
- architecture test：`internal/harness` 不 import adapters。
- E2E：构造两个 run，修改 AGENTS.md / tool set / permission mode，验证 harness diff 输出。

## 14. 发布标准

v0.3 可以发布的条件：

- `go test ./...` 通过。
- `go vet ./...` 通过。
- E2E 通过。
- README 明确 v0.3 是 HarnessMetadata / Pairwise HarnessDiff。
- docs 不恢复 Matrix/Regression 主线。
- harness diff 输出能解释两个 run 的 harness 差异，但不声称因果。
- v0.2 behavior 命令未破坏。
