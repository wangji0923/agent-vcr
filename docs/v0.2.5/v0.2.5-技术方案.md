# agent-vcr v0.2.5 技术方案：Behavior Visualization

## 1. 版本定位

v0.2.5 的目标不是新增新的分析理论，而是把 v0.2 已经产出的 `behavior.Step`、`BehaviorSignature`、`Divergence`、`Metrics` 可视化。

一句话定位：

> **Visualize and compare AI coding agent behavior paths.**
>
> 展示一个或多个 agent run 的行为路径，并高亮同一提示词下不同 agent / 不同 run 的探索路径分叉。

v0.2.5 关注的是：

- 单 run：这个 agent 是怎么探索、阅读、修改、验证的。
- 双 run：同一个 prompt 下，两个 run 从哪里开始走向不同的行为路径。
- 多 run：手动选择 3-5 个 run，按泳道展示每个 run 的行为路径差异。

v0.2.5 不做：

- HarnessMetadata / HarnessDiff，这是 v0.3。
- Matrix Compare / benchmark runner。
- Behavior Regression / baseline。
- 新 agent adapter。
- LLM explain。
- deterministic replay。
- cloud dashboard。

## 2. 当前上下游关系

v0.2.5 依赖 v0.2 的行为层：

```text
trace.ndjson
  ↓
behavior.Timeline
  ↓
behavior.Signature
  ↓
behavior.Divergence / behavior.Metrics
  ↓
visualize.VisualReport
  ↓
JSON / HTML
```

v0.2.5 不直接理解 Codex / Claude / Kimi。它只消费 normalized trace 和 behavior 数据。

## 3. 目标用户体验

### 3.1 单 run 可视化

```bash
agent-vcr visualize latest --html --output run.html
```

页面展示：

- run summary
- behavior timeline
- file access timeline
- metrics cards
- raw event drill-down

### 3.2 双 run 对比

```bash
agent-vcr visualize run-a run-b --html --output compare.html
```

页面展示：

- first divergence summary
- 双泳道对齐时间线
- 文件访问对比
- metrics 对比卡
- step drill-down

### 3.3 多 run 对比

```bash
agent-vcr visualize run-a run-b run-c --html --output multi.html
```

页面展示：

- 多泳道 timeline
- 以第一个 run 作为 baseline 的 divergence 标记
- 文件访问矩阵
- metrics 横向对比

限制：v0.2.5 不做复杂多序列全局最优对齐，默认采用“baseline 对齐”策略。

## 4. 核心视图

### 4.1 双泳道对齐时间线

这是 v0.2.5 主视图。

要求：

- 每个 run 一条 lane。
- 每个 step 显示 kind、summary、files、command 摘要。
- 相似 step 对齐到同一行。
- first divergence 高亮。
- 支持展开查看 event_id、source refs、原始命令、文件路径。

示例：

```text
Row  Run A                                  Run B
1    search "session"                      search "session"
2    read tests/session.test.js             read src/session.js   ← divergence
3    read src/session.js                    edit src/session.js
4    edit src/session.js                    finish
5    run npm test                           -
```

### 4.2 行为路径图

把 behavior step 抽象成路径图：

```text
Prompt → Search → Read Test → Read Source → Edit Source → Run Test → Finish
```

多 run 对比时：

- baseline 路径用主线。
- 其他 run 在分叉处显示不同路径。
- v0.2.5 可先用简单 SVG，不依赖前端框架。

### 4.3 文件访问对比

展示每个文件在不同 run 中的使用方式：

```text
File                                      Run A          Run B
src/session.js                            read/edit      edit
tests/session.test.js                     read           -
src/legacy-cookie.js                      -              read/edit
```

每个文件记录：

- read_count
- edit_count
- first_step
- last_step
- first_action
- last_action

### 4.4 Metrics Cards

基于 v0.2 metrics 展示：

- Context discipline
- Validation behavior
- Edit scope
- Tool efficiency
- Recovery behavior

示例：

```text
Read tests before edit: A yes / B no
Validation runs: A 1 / B 0
Edited files: A 1 / B 2
Searches: A 2 / B 1
```

## 6. 数据模型

### 6.1 VisualReport

```go
type VisualReport struct {
    SchemaVersion string              `json:"schema_version"`
    GeneratedAt   time.Time           `json:"generated_at"`
    Runs          []VisualRun          `json:"runs"`
    Lanes         []BehaviorLane       `json:"lanes"`
    Alignment     []AlignmentRow       `json:"alignment"`
    Divergences   []VisualDivergence   `json:"divergences"`
    FileAccess    FileAccessCompare    `json:"file_access"`
    Metrics       []RunMetricsCards    `json:"metrics"`
    PathGraph     *PathGraph           `json:"path_graph,omitempty"`
    Warnings      []string             `json:"warnings,omitempty"`
}
```

### 6.2 VisualRun

```go
type VisualRun struct {
    RunID        string            `json:"run_id"`
    Label        string            `json:"label"`
    Source       string            `json:"source"`
    Status       string            `json:"status"`
    StartedAt    *time.Time        `json:"started_at,omitempty"`
    EndedAt      *time.Time        `json:"ended_at,omitempty"`
    StepCount    int               `json:"step_count"`
    Summary      map[string]any    `json:"summary,omitempty"`
}
```

### 6.3 BehaviorLane / VisualStep

```go
type BehaviorLane struct {
    RunID string       `json:"run_id"`
    Label string       `json:"label"`
    Steps []VisualStep `json:"steps"`
}

type VisualStep struct {
    StepID      string            `json:"step_id"`
    Index       int               `json:"index"`
    Kind        string            `json:"kind"`
    Summary     string            `json:"summary"`
    Query       string            `json:"query,omitempty"`
    Command     string            `json:"command,omitempty"`
    Files       []string          `json:"files,omitempty"`
    Target      string            `json:"target,omitempty"`
    EventIDs    []string          `json:"event_ids,omitempty"`
    Significant bool              `json:"significant"`
    Divergent   bool              `json:"divergent"`
    Attributes  map[string]string `json:"attributes,omitempty"`
}
```

### 6.4 AlignmentRow

```go
type AlignmentRow struct {
    RowIndex    int                  `json:"row_index"`
    Cells       map[string]*StepCell  `json:"cells"`
    IsDivergent bool                 `json:"is_divergent"`
    Reason      string               `json:"reason,omitempty"`
}

type StepCell struct {
    RunID  string      `json:"run_id"`
    Step   *VisualStep `json:"step,omitempty"`
    Gap    bool        `json:"gap"`
}
```

### 6.5 FileAccessCompare

```go
type FileAccessCompare struct {
    Rows []FileAccessRow `json:"rows"`
}

type FileAccessRow struct {
    Path string             `json:"path"`
    Runs map[string]FileUse `json:"runs"`
}

type FileUse struct {
    ReadCount   int    `json:"read_count"`
    EditCount   int    `json:"edit_count"`
    FirstStep   int    `json:"first_step"`
    LastStep    int    `json:"last_step"`
    FirstAction string `json:"first_action,omitempty"`
    LastAction  string `json:"last_action,omitempty"`
}
```

## 7. 对齐算法

v0.2.5 使用 baseline 对齐。

### 7.1 单 run

单 run 不需要对齐，直接生成一条 lane。

### 7.2 双 run

使用 `behavior.Signature` 中的 fingerprint 或 `VisualStep` 的 normalized key 做 LCS / 动态规划对齐。

候选对齐 key：

```text
kind + normalized target + normalized query + normalized command kind
```

对齐权重：

- kind 相同：+3
- target/file 相同：+3
- query 相同：+2
- command kind 相同：+1
- edit/read/test kind 差异大：-3

### 7.3 多 run

以第一个 run 为 baseline：

- baseline vs run2 生成 alignment。
- baseline vs run3 生成 alignment。
- 合并成多 lane rows。
- 不做 N 序列全局最优对齐。

## 8. HTML 报告

### 8.1 技术约束

- 使用 Go `html/template`。
- 静态 HTML，离线可打开。
- 不引入 npm / React / Vue / build pipeline。
- 可用少量内联 JS 做折叠、过滤、高亮。
- 所有用户内容必须 HTML escape。
- report/export 必须应用 redaction。

### 8.2 页面结构

```text
Header
  run labels / generated at / source / status

Summary
  first divergence
  key metrics cards
  warnings

Swimlane Timeline
  aligned rows
  expandable step details

Path Graph
  simple SVG behavior path

File Access Compare
  file rows x run columns

Metrics Cards
  per-run and pairwise compare

Raw References
  event ids / artifacts references
```

## 9. CLI 设计

新增命令：

```bash
agent-vcr visualize <run-id|latest> [run-id...] --html --output behavior.html
agent-vcr visualize <run-id|latest> [run-id...] --json
```

参数：

```text
--html              generate static HTML
--json              output VisualReport JSON
--output <path>     output path
--label <k=v>       optional run labels, repeatable
--max-runs <n>      default 5
--no-cache          rebuild behavior from trace
--baseline <run-id> optional baseline, default first run
```

示例：

```bash
agent-vcr visualize latest --html
agent-vcr visualize run-a run-b --html --output compare.html
agent-vcr visualize run-a run-b run-c --json
```

## 10. 缓存策略

v0.2.5 不需要新增复杂缓存。优先读取 v0.2 的 behavior cache：

```text
.agent-vcr/runs/<run-id>/behavior/signature.json
```

如果不存在：

```text
trace.ndjson → behavior.Timeline → Signature → VisualReport
```

可选输出：

```text
.agent-vcr/runs/<run-id>/visual/visual-report.json
```

但不要让 visualize 必须依赖该缓存。
