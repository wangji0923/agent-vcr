# agent-vcr v0.2 实施方案：分模块开发计划

## 1. 总体执行原则

v0.2 只做 BehaviorSignature 与 first behavior divergence。不要扩展到 v0.3/v0.4 功能。

硬约束：

```text
1. internal/behavior 不得 import internal/adapters/*
2. 不改 trace.Event 既有语义
3. 不实现 HarnessMetadata / HarnessDiff
4. 不实现 Matrix / Regression
5. 不引入 LLM API
6. 不新增 Claude/Kimi/MCP adapter
7. 所有新增命令必须支持 --json
8. 所有新增行为抽取规则必须有测试
```

## 2. 模块拆分

建议按 8 个模块实施：

```text
01-behavior-domain-model
02-event-to-behavior-extractor
03-command-and-path-classifiers
04-behavior-signature-and-cache
05-first-behavior-divergence
06-behavior-metrics
07-cli-integration-and-output
```

v0.2 新增接口应集中在 `internal/behavior`。不要在第一轮开发时让多个 subagent 同时修改这些核心类型：


先由主控或 01 模块锁定，再并行开发。

## 8. 总体验收命令

每轮结束运行：

```powershell
gofmt -w .
go test ./...
go vet ./...
go build ./cmd/agent-vcr
go run ./cmd/agent-vcr --help
```

最终额外运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\e2e.ps1
go run ./cmd/agent-vcr behavior latest --json
go run ./cmd/agent-vcr behavior diff <run-a> <run-b> --json
go run ./cmd/agent-vcr behavior metrics latest --json
```

## 9. 风险点

### 9.1 行为抽取过度解释

v0.2 应避免“智能解释”。所有 interpretation 必须来自规则模板，不能假装理解模型意图。

### 9.2 分类规则过窄

命令分类要可扩展，不要把所有逻辑写死在一个函数里。建议拆 `command_classifier.go` 和 `path_classifier.go`。

### 9.3 first divergence 被噪声污染

行为 diff 必须忽略 timestamp、event index、绝对用户路径、blob path、source event id 等不稳定信息。

### 9.4 和 v0.3 混淆

不要在 v0.2 引入 HarnessMetadata。可以在 docs 中写 future plan，但代码不要实现。
