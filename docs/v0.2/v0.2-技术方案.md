# agent-vcr v0.2 技术方案：BehaviorSignature + First Behavior Divergence

## 1. 背景

v0.1 已经完成了本地 trace 底座：Codex hook、Codex JSONL、Generic CLI、normalized trace、list、replay、event-level diff、check、export、doctor。

v0.1 的 `diff` 主要比较 `trace.Event` 层面的事件差异，例如 tool name、shell command、changed files、exit code。这个能力已经能定位一些差异，但还没有回答 agent-vcr 的核心问题：

> 同一个任务、同一个模型，不同 harness，为什么 Agent 行为路径不一样？

v0.2 的目标是把低层事件抽象成更稳定、更有语义的 **BehaviorSignature**，并基于 BehaviorSignature 提供真正的 **First Behavior Divergence**。

## 2. v0.2 目标

v0.2 只做四件事：

1. 从 normalized `trace.Event` 中抽取 `behavior.Step`。
2. 基于 `behavior.Step` 生成 `BehaviorSignature`。
3. 基于两个 `BehaviorSignature` 找到 first behavior divergence。
4. 计算基础 behavior metrics，用于解释行为差异。

v0.2 的用户问题是：

```text
同一个任务，Run A 成功，Run B 失败。
不是问最终代码差异是什么，而是问：
- 行为第一次从哪里分叉？
- Run A 为什么先读测试？
- Run B 为什么先进入 legacy 文件？
- 哪个 run 跳过了验证？
- 哪个 run 修改范围更大？
```

## 3. 非目标

v0.2 明确不做：

```text
- HarnessMetadata
- HarnessDiff
- Matrix Compare
- Benchmark runner
- Baseline / Regression
- PR Risk Score
- Cloud dashboard
- LLM Explain
- Deterministic Replay
- 新增 Claude/Kimi/MCP adapter
- 大改 trace schema
- 修改 v0.1 trace storage 兼容性
```

HarnessMetadata / HarnessDiff 留到 v0.3；Pairwise Compare Report 留到 v0.4。

## 4. 总体架构

v0.2 在 v0.1 的 trace 基础上新增 `internal/behavior`：

```text
Codex / Generic / JSONL Adapter
        ↓
normalized trace.Event
        ↓
internal/behavior Extractor
        ↓
behavior.Step[]
        ↓
BehaviorSignature
        ↓
BehaviorDiff / FirstDivergence / BehaviorMetrics
        ↓
CLI: behavior latest / behavior diff / behavior metrics
```

重要边界：

```text
internal/behavior 不得 import internal/adapters/*
internal/behavior 只能依赖 trace.Event、metadata、blobs、patches、config、git/path helper
```

## 5. 核心概念

### 5.1 trace.Event

v0.1 的通用事件，是底层事实记录。示例：

```json
{
  "type": "shell_command",
  "payload": {
    "command": "npm test"
  }
}
```

### 5.2 behavior.Step

v0.2 新增的行为语义单元。它把底层事件抽象为 agent 行为：

```json
{
  "kind": "run_test",
  "action": "npm test",
  "target": "project",
  "source_event_ids": ["evt_012", "evt_013"],
  "result": "failed",
  "confidence": 0.95
}
```

### 5.3 BehaviorSignature

一次 run 的行为签名。它是用于 diff 的主要对象：

```json
{
  "schema_version": "0.1",
  "run_id": "2026-06-04-auth-a",
  "source_trace_hash": "sha256:...",
  "steps": [...],
  "metrics": {...}
}
```

### 5.4 BehaviorDiff

两个 BehaviorSignature 的 pairwise diff：

```json
{
  "run_a": "run-a",
  "run_b": "run-b",
  "first_divergence": {...},
  "metrics_delta": {...},
  "summary": {...}
}
```

## 7. 事件到行为的抽取规则

### 7.1 shell command 分类

命令模式：

```text
rg / grep / find / fd            → search
cat / sed -n / head / tail       → read_file，若能解析路径
npm test / pnpm test / yarn test → run_test
pytest / go test / cargo test    → run_test
npm run build / go build         → run_build
npm install / pnpm add           → install_dependency
```

### 7.2 file patch / apply_patch

```text
file_patch / apply_patch → edit_file
```

如果 patch 文件命中测试路径，则标记：

```text
attributes["path_kind"] = "test"
```

### 7.3 tool_call 分类

```text
mcp__*                         → call_mcp_tool
Bash / shell.exec              → 根据 command 二次分类
Read / Open / View / read_file → read_file
Edit / Write / apply_patch     → edit_file
unknown tool                   → call_tool
```

### 7.4 test inspection

如果 `read_file` 目标路径符合测试路径：

```text
tests/**
**/*_test.go
**/*.test.*
**/*.spec.*
```

则提升为：

```text
inspect_test
```

### 7.5 recovery behavior

如果某个失败命令之后，agent 继续：

```text
read error log
edit file
rerun test
```

可以生成 `recover_from_error`。v0.2 可以先做基础规则：

```text
失败的 run_test / run_build 之后，出现 edit_file 或 read_file，即标记 recovery evidence
```

不要过度解释。只输出规则事实。

## 8. Behavior Diff 算法

### 8.1 生成 Step Signature Key

每个 Step 生成稳定 key：

```text
kind + normalized action + normalized target + normalized files + normalized result
```

忽略：

```text
timestamp
index
absolute user path
blob path
source_event_id 的随机差异
```

### 8.2 First Divergence

基础算法：

```text
1. 生成 Run A steps
2. 生成 Run B steps
3. 将每个 step 转成 signature key
4. 从前往后比较
5. 第一个 key 不同的位置即 first behavior divergence
6. 若一方结束而另一方还有行为，则 divergence kind = missing_step / extra_step
```

v0.2 不需要复杂 LCS。先实现线性 first divergence 即可。后续可引入 alignment。

### 8.3 Diff 输出

输出应该包含：

```text
run_a_step
run_b_step
divergence_index
kind
human summary
metrics delta
```

示例：

```text
First behavior divergence at step 3

Run A:
  inspect_test tests/auth/session.test.ts

Run B:
  read_file src/auth/legacy-cookie.ts

Impact:
  Run B entered legacy implementation path before inspecting tests.
```

注意：Impact 文案必须来自规则模板，不能假装模型理解。

## 10. CLI 设计

新增顶层命令组：

```bash
agent-vcr behavior latest
agent-vcr behavior diff run-a run-b
agent-vcr behavior metrics latest
```

### 10.1 `behavior latest`

输出行为 timeline。

```text
# Behavior timeline: latest
1. search      rg "session" src tests
2. inspect_test tests/auth/session.test.ts
3. read_file   src/auth/session.ts
4. edit_file   src/auth/session.ts
5. run_test    npm test → success
```

支持：

```bash
agent-vcr behavior latest --json
```

### 10.2 `behavior diff`

```bash
agent-vcr behavior diff run-a run-b
agent-vcr behavior diff run-a run-b --json
```

### 10.3 `behavior metrics`

```bash
agent-vcr behavior metrics latest
agent-vcr behavior metrics latest --json
```

## 11. 存储策略

v0.2 默认可以按需计算，不强制落盘。可选生成：

```text
.agent-vcr/runs/<run-id>/behavior.json
```

建议实现：

```bash
agent-vcr behavior latest --write-cache
```

但 v0.2 初版可以只做内存计算。若做缓存，必须保证 trace 改变后缓存失效。

## 12. 兼容性

v0.2 必须读取 v0.1 trace。

兼容原则：

```text
- 不改 trace.Event 语义
- 不要求 v0.1 trace 有新字段
- 无法识别的事件转为 raw_behavior 或跳过
- behavior 结果可降级，不 panic
```
