# Agent VCR 技术方案

> 版本：v0.2 草案
> 日期：2026-06-04
> 定位：AI Coding Agent 的 Behavior Diff / Harness Diff 基础设施
> 第一版范围：Codex CLI / Codex 客户端优先，架构必须保留多 Agent Adapter 扩展能力

---

## 0. 本次修订重点

本版相对上一版做了 5 个关键收紧：

1. **Codex 只能存在于 Adapter 层**，不能污染 Trace Store、Replay、Diff、Check、Report 等核心模块。
2. 新增 **Adapter Registry**，后续新增 Claude、Kimi、自研 SDK、MCP Proxy、JSONL Stream、Generic CLI 时只新增 adapter。
3. 新增 **Capabilities 能力声明**，每个 adapter 必须声明自己能采集哪些事件，避免“所有 agent 都能完整采集”的虚假承诺。
4. 新增 **RawEvent 兜底机制**，当外部协议变化或 normalize 失败时，保留原始事件，不阻塞 agent。
5. 新增 **SDK / HTTP Ingest / MCP Proxy 预留设计**，支持用户把本项目接入自己的 agent 框架。

最终架构边界：

```text
错误路线：Codex Hook → Report
正确路线：Adapter → Normalized Trace → Replay / Diff / Check / Export
```

## 1. 背景与问题

AI Coding Agent 正在从“聊天辅助”变成“能实际修改仓库、执行命令、打开 PR 的执行者”。开发者已经能在 Codex、Claude Code、Kimi Code、Cursor、Cline、LangGraph 等工具里看到部分执行过程，但这些过程通常只是当前会话里的实时展示，不一定能被稳定保存、复盘、对比、规则检查和作为 CI artifact 使用。

本项目解决的问题不是“看 agent 当前在干什么”，而是：

```text
把一次 agent run 变成稳定的行为证据：
可保存、可回放、可对比、可规则检查、可脱敏分享、可进入 CI。
```

核心问题：

- 同一个任务两次 agent run 结果不同，无法定位第一次分叉点。
- Agent 修改了很多文件，reviewer 只能看到最终 diff，看不到它执行过哪些步骤。
- Agent 没有跑测试、修改敏感文件、读取 secret、执行危险命令，事后难以自动检查。
- 不同 agent 暴露的事件协议不同，缺少统一的运行轨迹格式。
- 现有 agent transcript 多用于自身 resume，不适合作为稳定的外部审计数据源。

---

## 2. 产品一句话

```text
Agent VCR 是 AI Coding Agent 的 Behavior Diff / Harness Diff 工具。
Same model. Same task. Different harness.
它通过 hooks、JSONL stream 或通用 CLI wrapper 采集 agent 行为，统一转成 trace.ndjson，然后显示两次 run 的行为从哪里开始分叉。
```

第一版更窄：

```text
Codex first, adapter-ready.
```

即：v0.1 一等支持 Codex CLI 与 Codex 客户端，但架构上不能写死 Codex。
当前 diff 是 event-level behavior diff；BehaviorSignature 与 HarnessMetadata 是后续版本路线。

## 3. 目标与非目标

### 3.1 v0.1 目标

1. 支持 Codex CLI 交互模式，通过 Codex hooks 采集运行过程。
2. 支持 Codex CLI 非交互模式，通过 `codex exec --json` JSONL stream 采集运行过程。
3. 支持 Codex 客户端 / IDE extension 的基础采集，依赖 Codex CLI 与 IDE / App 共享配置层。
4. 支持 Generic CLI Wrapper：任何 CLI agent 至少能记录进程输出与最终 git diff。
5. 提供统一 `trace.ndjson` schema。
6. 提供本地 run artifact 存储结构。
7. 提供 `replay`：回放 timeline。
8. 提供 `diff`：对比两次 run，输出 first divergence。
9. 提供 `check`：基于规则检查 agent run。
10. 提供 `export --html`：导出静态 HTML 报告。
11. 提供 `redact`：脱敏敏感信息。
12. 默认不要求额外大模型 API。
13. 提供 event-level behavior diff 底座，用于 pairwise run 对比。

### 3.2 v0.1 非目标

- 不记录模型私有 chain-of-thought。
- 不承诺 deterministic replay，即不重新模拟 LLM 与工具执行。
- 不做云端 SaaS。
- 不默认上传源码、prompt、日志到任何远端。
- 不替代 Codex / Claude Code / Kimi Code 本身。
- 不承诺完整安全边界；hook 记录和轻量检查不能替代 sandbox、权限审批和人工确认。
- 不在第一版支持所有 agent；仅通过 adapter 架构预留扩展。
- 不把 Codex transcript 内部格式当成核心数据源。
- 不实现 BehaviorSignature / HarnessMetadata / HarnessDiff。
- 不做 batch matrix runner、benchmark 平台、PR risk scoring 产品或 LLM explain。

## 5. 分层职责与硬性边界

### 5.1 Adapter 层

Adapter 层负责处理外部 agent 协议差异。

职责：

- 探测 agent 是否存在。
- 安装 hook 或配置 wrapper。
- 接收原始事件。
- 将原始事件转为统一 trace.Event。
- 声明 adapter capabilities。
- 在 normalize 失败时输出 RawEvent。

允许依赖：

```text
internal/trace
internal/config
internal/gitutil
internal/redact
```

### 5.2 Trace Core 层

Trace Core 负责稳定存储。

职责：

- 定义统一事件 schema。
- 创建 run 目录。
- 写入 metadata、trace.ndjson、blob、patch。
- 提供文件锁和并发写入保护。
- 提供 run resolver，例如 latest、by-id、list。

禁止依赖：

```text
internal/adapters/*
```

### 5.3 Analysis 层

Analysis 层负责读取 normalized trace 并分析。

职责：

- replay timeline。
- diff 两次 run。
- check 规则。
- export 报告。
- redact 输出。

禁止依赖：

```text
internal/adapters/*
```

### 5.4 关键硬性约束

```text
1. internal/analysis 不得 import internal/adapters/*。
2. internal/report 不得 import internal/adapters/*。
3. internal/check 不得 import internal/adapters/*。
4. internal/trace 不得 import internal/adapters/*。
5. Codex 相关逻辑只能存在于 internal/adapters/codex 与 CLI init 分发层。
6. 新增 adapter 默认不允许修改 replay / diff / check 核心逻辑。
7. 如果必须修改 trace schema，必须增加 schema_version，并保证旧 trace 可读。
```

## 6. Adapter 体系

### 6.1 Adapter 接口

Go 伪代码：

```go
type Adapter interface {
    Name() string
    DisplayName() string
    Probe(ctx context.Context) (*ProbeResult, error)
    Install(ctx context.Context, opts InstallOptions) error
    Uninstall(ctx context.Context, opts InstallOptions) error
    Normalize(ctx context.Context, raw RawEvent) ([]trace.Event, error)
    Capabilities() Capabilities
}
```

### 6.2 Capabilities

```go
type Capabilities struct {
    PromptCapture      bool
    ModelCallCapture   bool
    ModelResultCapture bool
    ToolCallCapture    bool
    ToolResultCapture  bool
    ShellCapture       bool
    FileDiffCapture    bool
    PermissionCapture  bool
    SubagentCapture    bool
    MCPToolCapture     bool
    CanInstallHooks    bool
    CanRunAsWrapper    bool
    CanImportTrace     bool
    CanIngestHTTP      bool
}
```

Capabilities 用于：

- `agent-vcr doctor` 展示能力边界。
- HTML report 展示本次 run 可观测性级别。
- 避免低能力 adapter 被误判为漏采。
- 支持 future adapter 不需要一次性实现所有能力。

### 6.3 Adapter Registry

```go
type Registry struct {
    adapters map[string]Adapter
}

func Register(adapter Adapter)
func Get(name string) (Adapter, bool)
func List() []Adapter
```

CLI 调用必须通过 registry：

```text
agent-vcr init codex  → registry.Get("codex-hooks")
agent-vcr init kimi   → registry.Get("kimi-hooks")
agent-vcr record      → registry.Get("generic-cli")
```

禁止在 CLI 命令中写大量 `if adapter == "codex"` 的业务逻辑。

## 7. Adapter 类型规划

### 7.1 Native Hook Adapter

适合：Codex、Claude Code、Kimi Code 等有官方 hook 机制的 agent。

能力：

```text
PromptCapture      高
ToolCallCapture    高
ToolResultCapture  高
PermissionCapture  中到高
FileDiffCapture    通过 Git Snapshot 补齐
```

v0.1 实现：

```text
CodexHookAdapter
```

v0.2 可新增：

```text
ClaudeHookAdapter
KimiHookAdapter
```

注意：新增 adapter 的目标不是“支持更多 agent”本身，而是让更多 harness
产出可比较的 behavior trace。v0.2 主线不是批量扩 adapter，而是
BehaviorSignature。

### 7.2 Structured Stream Adapter

适合支持 JSONL / stream-json / wire mode 的 CLI agent。

v0.1 实现：

```text
CodexExecJsonlAdapter
```

### 7.3 SDK Trace / Callback Adapter

适合用户自研 agent 框架或 LangGraph / LangChain / OpenAI Agents SDK 等。

接入方式：

```python
with vcr.run(agent_name="my-agent", task="fix bug") as run:
    run.user_prompt("fix bug")
    with run.tool_call("shell.exec", {"command": "npm test"}) as span:
        result = exec("npm test")
        span.result(result)
```

v0.1 只预留 schema 与目录，不实现 SDK。

### 7.4 HTTP Ingest Adapter

适合多进程、跨语言、远程 sandbox agent。

```bash
agent-vcr collect --port 7821
```

事件写入：

```http
POST /v1/events
```

v0.1 不实现，但 schema 必须支持未来接入。

### 7.5 MCP Proxy Adapter

适合使用 MCP 工具的 agent。

```text
Agent → agent-vcr MCP Proxy → Real MCP Server
```

可记录：

- tools/list
- tools/call
- arguments
- result
- latency
- error

v0.1 不实现。

### 7.6 Generic CLI Wrapper Adapter

适合任意 CLI agent。

```bash
agent-vcr record -- some-agent "fix bug"
```

可记录：

- 进程开始 / 结束
- stdout / stderr
- exit code
- 运行前后 git diff
- 最终 changed files

v0.1 实现。

## 8. Unified Trace Schema

### 8.1 事件原则

统一事件必须具备：

```text
schema_version
run_id
event_id
type
source
timestamp
payload
raw_ref 可选
```

事件必须满足：

- 可追加写入。
- 可按 event_index 排序。
- 可保存 raw event。
- 可脱敏。
- 可跨 adapter 分析。

### 8.2 事件类型

```go
type EventType string

const (
    EventRunStart          EventType = "run_start"
    EventRunStop           EventType = "run_stop"
    EventUserPrompt        EventType = "user_prompt"
    EventModelCall         EventType = "model_call"
    EventModelResult       EventType = "model_result"
    EventToolCall          EventType = "tool_call"
    EventToolResult        EventType = "tool_result"
    EventToolError         EventType = "tool_error"
    EventFileRead          EventType = "file_read"
    EventFileWrite         EventType = "file_write"
    EventFilePatch         EventType = "file_patch"
    EventShellCommand      EventType = "shell_command"
    EventShellResult       EventType = "shell_result"
    EventPermissionRequest EventType = "permission_request"
    EventSubagentStart     EventType = "subagent_start"
    EventSubagentStop      EventType = "subagent_stop"
    EventContextCompact    EventType = "context_compact"
    EventProcessStart      EventType = "process_start"
    EventProcessResult     EventType = "process_result"
    EventRaw               EventType = "raw_event"
)
```

### 8.3 事件结构

```go
type Event struct {
    SchemaVersion string         `json:"schema_version"`
    EventID       string         `json:"event_id"`
    RunID         string         `json:"run_id"`
    ParentID      string         `json:"parent_id,omitempty"`
    SpanID        string         `json:"span_id,omitempty"`
    EventIndex    int64          `json:"event_index"`
    Type          EventType      `json:"type"`
    Source        EventSource    `json:"source"`
    Timestamp     time.Time      `json:"timestamp"`
    Payload       map[string]any `json:"payload,omitempty"`
    Artifacts     []ArtifactRef  `json:"artifacts,omitempty"`
    RawRef        *ArtifactRef   `json:"raw_ref,omitempty"`
}

type EventSource struct {
    Adapter      string `json:"adapter"`
    Agent        string `json:"agent,omitempty"`
    RawEventType string `json:"raw_event_type,omitempty"`
    Version      string `json:"version,omitempty"`
}
```

### 8.4 RawEvent 兜底

Normalize 失败时，不能丢数据，也不能阻塞 agent。

```json
{
  "schema_version": "0.2",
  "type": "raw_event",
  "source": {
    "adapter": "codex-hooks",
    "raw_event_type": "UnknownCodexEvent"
  },
  "raw_ref": {
    "kind": "blob",
    "path": "blobs/raw_evt_001.json",
    "sha256": "..."
  }
}
```

## 9. Trace Store

### 9.1 目录结构

```text
.agent-vcr/
  config.yml
  state/
    sessions.json
    locks/
  runs/
    2026-06-04-183000-s_123/
      metadata.json
      trace.ndjson
      blobs/
      patches/
      snapshots/
      report.html
```

### 9.2 metadata.json

```json
{
  "schema_version": "0.2",
  "run_id": "2026-06-04-183000-s_123",
  "source": "codex-hooks",
  "status": "running",
  "cwd": "/repo",
  "repo_root": "/repo",
  "git_sha": "abc1234",
  "branch": "feature/auth-fix",
  "started_at": "2026-06-04T18:30:00+08:00",
  "ended_at": null,
  "capabilities": {
    "prompt_capture": true,
    "tool_call_capture": true,
    "file_diff_capture": true
  }
}
```

### 9.3 并发安全

每次写入流程：

```text
resolve run_id
acquire lock
assign event_index
write blob if needed
append trace.ndjson
update metadata.json
release lock
```

必须支持多个 hook 并发触发。

## 10. Codex v0.1 接入方案

### 10.1 Codex Hook 接入

用户执行：

```bash
agent-vcr init codex
```

生成：

```text
.codex/hooks.json
.agent-vcr/config.yml
```

Codex 运行时触发：

```text
SessionStart
UserPromptSubmit
PreToolUse
PostToolUse
PermissionRequest
PreCompact
PostCompact
SubagentStart
SubagentStop
Stop
```

每次调用：

```bash
agent-vcr hook --adapter codex
```

约束：

- hook 默认 stdout 为空。
- hook 失败 exit 0。
- hook 不阻塞 Codex。
- hook 不直接做复杂分析，只写入 normalized trace。

### 10.2 Codex exec JSONL 接入

用户执行：

```bash
agent-vcr record -- codex exec --json "fix bug"
```

流程：

```text
spawn codex exec --json
逐行读取 stdout JSONL
normalize item.* 事件
stderr 进 blob
进程结束采集 final git diff
```

### 10.3 Codex 客户端接入

Codex CLI、IDE extension、App 共享配置层时，客户端在同一项目运行即可加载 `.codex/` 配置。使用流程：

```bash
cd repo
agent-vcr init codex
codex
# 在 /hooks 中 review / trust hook
# 然后正常使用 Codex 客户端
```

如果 Codex 实际运行在远程环境，则 `agent-vcr` 必须安装在 Codex 执行环境里。

## 11. Generic CLI v0.1 接入方案

```bash
agent-vcr record -- some-agent "fix bug"
```

可采集：

- process_start
- process_result
- stdout blob
- stderr blob
- before git snapshot
- after git snapshot
- final diff

不可采集：

- 内部 tool call
- 模型调用
- prompt 精确结构
- 权限请求

Generic CLI Adapter 的价值是兜底：

```text
Deep integration for supported agents.
Best-effort recording for any CLI agent.
```

## 12. 自研 Agent 框架接入预留

### 12.1 Python SDK 预留

```python
from agent_vcr import AgentVCR

vcr = AgentVCR(project_dir=".")

with vcr.run(agent_name="my-agent", task="fix auth bug") as run:
    run.user_prompt("fix auth bug")
    with run.model_call(provider="openai", model="gpt-5.5", input=messages) as span:
        response = llm.chat(messages)
        span.output(response)
    with run.tool_call(name="shell.exec", args={"command": "npm test"}) as span:
        result = exec("npm test")
        span.result(result)
```

### 12.2 TypeScript SDK 预留

```ts
const vcr = new AgentVCR({ projectDir: "." });

await vcr.run({ agentName: "my-agent", task: "fix auth bug" }, async (run) => {
  run.userPrompt("fix auth bug");
  await run.toolCall({ name: "shell.exec", args: { command: "npm test" } }, async () => {
    return await exec("npm test");
  });
});
```

### 12.3 HTTP Ingest 预留

```http
POST /v1/events
Content-Type: application/json

{
  "run_id": "run_123",
  "type": "tool_call",
  "payload": {
    "tool_name": "search",
    "args": {"query": "auth bug"}
  }
}
```

v0.1 不实现 SDK 和 HTTP collector，但 trace schema 必须能承载这些事件。

## 13. Analysis 能力

### 13.1 Replay

输入：

```text
metadata.json
trace.ndjson
blobs/
patches/
```

输出：

```text
timeline
工具调用合并
命令结果
文件变化
最终状态
```

禁止识别 Codex 原始事件名，只识别 normalized event type。

### 13.2 Diff

目标：输出 first divergence。

策略：

- 标准化事件签名。
- 忽略 timestamp / duration 微小差异。
- 以 event type + tool name + args hash + result hash 对齐。
- 使用简化 LCS 或顺序扫描找第一次分叉。

### 13.3 Check

检查规则：

- forbidden_paths。
- required_commands。
- max_changed_files。
- require_tests_after_source_change。
- secret pattern。
- dangerous shell commands。

### 13.4 Export HTML

静态 HTML，本地打开，无远程资源。

## 14. 隐私与安全

默认策略：

```text
.agent-vcr/ 加入 .gitignore
redaction.enabled = true
.env / token / private key 默认脱敏
hook 默认不上传任何数据
核心功能不需要额外大模型 API
```

必须提供：

```bash
agent-vcr redact latest
```
